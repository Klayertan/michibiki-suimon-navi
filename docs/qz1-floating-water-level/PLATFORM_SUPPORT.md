# プラットフォーム対応 / Platform Support

スイスイナビは iPhone / iPad / macOS / Windows / Android の各ブラウザで動きます。
**ただし「動く」は「どの端末でも同じ方法でQZ1につながる」という意味ではありません。**

---

## 1. 原則 / Universal ≠ identical

```text
ユニバーサルなアプリ
≠
すべてのブラウザですべての接続方法が使える

ユニバーサルなアプリ
=
同じセンサーモデル
同じ圃場モデル
同じ測定フォーマット
同じ解析
同じUI概念

＋

その端末で実際に使える最良の取得経路
```

同じ正規化済み測定値が、どの経路で届いても**同じ下流パイプライン**に入ります。
Safari用・Chrome用・iPhone用の別実装は作っていません。

```text
   シリアル ─┐
Bluetooth ─┤
    ファイル ─┼──▶ 正規化測定値 ──▶ レジストリ ──▶ 圃場検出 ──▶ 水管理
   クラウド ─┘
```

---

## 2. 検出方法 / Feature detection, not browser sniffing

```javascript
"serial" in navigator      // ブラウザ名は見ない
"bluetooth" in navigator
window.isSecureContext
```

UA文字列で分岐していません。UAは設計上あてになりませんし、将来Safariが
対応した日に機能検出なら自動的に正しくなります。

**唯一の例外**は `iosLikeBluetoothBlock` で、これは機能検出が既に出した
否定的結果の**説明文を選ぶためだけ**に使います。判定には使いません。
iOSでは全ブラウザがWebKitなので「Chromeを入れてください」は誤った助言に
なり、その違いだけは機能検出できないためです。

## 3. 対応表 / Support matrix

**2つのゲートがあります。**

1. **ブラウザが対応しているか**（実行時に機能検出）
2. **このアプリに実装があるか**（`IMPLEMENTED_TRANSPORTS`）

両方を満たす経路だけが選択可能になります。

### 3.1 ブラウザのAPI対応（一般に知られている状況）

| プラットフォーム | Web Serial | Web Bluetooth | ファイル読込 |
|---|---|---|---|
| macOS Chrome / Edge | ✓ | ✓ | ✓ |
| Windows Chrome / Edge | ✓ | ✓ | ✓ |
| Linux Chrome / Edge | ✓ | ✓ | ✓ |
| macOS Safari | ✗ | ✗ | ✓ |
| Firefox（全OS） | ✗ | ✗ | ✓ |
| Android Chrome | ✗ | ✓ | ✓ |
| **iPhone / iPad（全ブラウザ）** | ✗ | ✗ | ✓ |

* Web Serial は Chromium系の**デスクトップのみ**。Android Chromeにはありません。
* iOSは全ブラウザがWebKitなので、Chrome/Edge/Firefoxを入れても結果は同じです。
* いずれもHTTPS（またはlocalhost）が必要です。

> この表は参考情報です。**実際の可否は実行時の機能検出が決めます。**
> カードの「この端末で使える接続方法」に、その端末の本当の結果が出ます。

### 3.2 このアプリの実装状況

| 経路 | 実装 | 備考 |
|---|---|---|
| USB / シリアル | **実装済み** | index.html の既存Web Serialパイプラインを利用。QZ1のBluetooth SPP仮想ポートもここに含まれます |
| NMEAファイル読込 | **実装済み** | 既存のNMEAアップローダを利用。**全端末で利用可能** |
| Bluetooth (GATT) | **未実装** | GATTクライアントがありません |
| クラウド / ゲートウェイ | **未実装** | 受信エンドポイントがありません |

### 3.3 実際に使える経路（両方のゲートを通ったもの）

| プラットフォーム | 直接接続 | ファイル読込 | クラウド | 備考 |
|---|---|---|---|---|
| macOS Chrome / Edge | **✓ シリアル** | ✓ | ✗ 未実装 | 完全な直接接続 |
| Windows Chrome / Edge | **✓ シリアル** | ✓ | ✗ 未実装 | 完全な直接接続 |
| macOS Safari | ✗ | ✓ | ✗ 未実装 | ファイル読込で運用 |
| Firefox（全OS） | ✗ | ✓ | ✗ 未実装 | ファイル読込で運用 |
| Android Chrome | ✗ | ✓ | ✗ 未実装 | Web SerialがAndroidにないため |
| **iPhone / iPad** | ✗ | ✓ | ✗ 未実装 | ファイル読込で運用 |

## 4. iPhone / iPad での案内 / The honest iOS message

直接接続できない端末では、次のように表示します。

```text
この端末で使える接続方法

USB / シリアル接続    利用不可（このブラウザは対応していません）
Bluetooth (GATT)      利用不可（このブラウザは対応していません）
NMEAファイル読込      利用可能
クラウド / ゲートウェイ 利用不可（このアプリで未実装です）

iPhone/iPadのブラウザは直接接続用のAPIに対応していません。
NMEAファイル読込またはクラウド経由でご利用ください。
センサーが故障しているわけではありません。
```

**押せないボタンは出しません。** 使えない経路は理由つきで無効表示にします。

**「ブラウザが対応していない」と「このアプリが未実装」を区別します。**
後者をブラウザのせいにするのは嘘だからです。デスクトップChromiumでは
Bluetoothは「このアプリで未実装です」と表示されます。

## 5. 設定の可搬性 / One record, many platforms

同じセンサーレコードが、設定したPCでも、圃場へ持ち出したスマホでも動きます。

* 接続方法の既定は `自動` — その端末で使える最良の経路を選びます
* 特定の経路を指定していて、その端末で使えない場合は**失敗せずフォールバック**し、
  「指定どおりではない」ことをUIが言えるよう `fellBack` を返します

## 6. Cloudflare での配信 / Deployment

本番は Cloudflare Workers（静的アセット）で配信します。
[docs/CLOUDFLARE_DEPLOYMENT.md](../CLOUDFLARE_DEPLOYMENT.md)。

センサー機能に関係する点:

* **HTTPS必須。** Web Serial / Web Bluetooth はセキュアコンテキストでのみ
  使えます。Cloudflare配信はHTTPSなので条件を満たします
* `localhost` / `127.0.0.1` を本番ロジックに埋め込んでいません
* 新規モジュールは `js/` 配下なので、ビルドの許可リスト（`ASSET_ROOTS`）に
  そのまま含まれます
* **ビルドは `git ls-files` を使います。** 未コミットの新規モジュールは
  `npm run build` が失敗して知らせます（本番で404になる前に止まります）

## 7. オフライン / Offline

クラウドが使えなくても、既存アーキテクチャの範囲で次は動きます。

* 圃場の登録・編集
* センサーの登録・設定・割り当て
* NMEAファイル読込
* 既存のローカル記録

センサーレジストリは `localStorage`（アカウントスコープ済み）に保存されます。
`localStorage` が書けない環境（プライベートブラウジング等）は検出し、
メモリ内で動作を継続します — 例外で停止させません。

## 8. 将来のゲートウェイ / Future gateway (planned)

```text
圃場

QZ1LE
   │
   ├── 直接ブラウザ接続（対応端末）
   │
   または
   │
   └── ゲートウェイ（未実装）
            ↓
       Wi-Fi / LoRa
            ↓
       Cloudflare
            ↓
        スイスイナビ
```

**このマイルストーンではLoRaもゲートウェイも実装していません。**
ただし正規化測定値のインターフェースは取得元を問わないので、
後からゲートウェイを足してもセンサー/圃場ロジックは変わりません。

`/api/*` は Cloudflare 側で将来のWorker用に確保済みです。
