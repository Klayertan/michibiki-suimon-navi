# Experimental Procedure

第1段階（固定治具）と第2段階（浮体）の手順。**どちらも未実施です。**

---

## 0. なぜこの順番か / Why the rig comes first

浮体から始めると、結果が悪かったときに原因が特定できません。GNSSの鉛直精度が
足りないのか、浮体が波で揺れているのか、ケーブルが張っているのか、アンテナが
傾いているのか——全部が同時に効いてきます。

固定治具の実験は **GNSS だけ** を切り出します。ここで 10 mm が読めないなら、
浮体で読める理由はありません。ここで読めるなら、第2段階との差が「浮体・水面・
係留が持ち込んだ分」です。

---

## 1. 第1段階: 固定治具による鉛直変位 / Controlled vertical displacement

### 1.1 必要なもの

* QZ1 / QZ1LE と外部低電圧給電
* **剛性のある鉛直基準**。以下のいずれか:
  * 厚みが実測済みのブロック（ゲージブロック、金属板、機械加工した端材）
  * ラボジャッキ（目盛を信用せず、必ず実測）
  * 目盛を刻んだ支柱＋クランプ
* **ノギスまたはマイクロメータ** — 基準高さの実測用
* Chrome / Edge が動くPC（Web Serial は HTTPS または localhost が必要）
* 空が開けた場所。建物の壁際・軒下は避ける

> **基準そのものの精度が上限です。** 10 mm の段差を ±2 mm でしか作れないなら、
> 誤差 ±2 mm は受信機ではなく治具のものです。使ったブロックの実測値を
> `notes` に書いてください。「10 mm」ではなく「実測 10.15 mm のブロック」です。

### 1.2 設置

1. 受信機を治具に**しっかり**固定する。実験中に緩んだら、その分が全部誤差になります
2. アンテナは上向き、金属から離す
3. **水平位置を変えないこと。** 鉛直だけを動かします。水平に動かすと、マルチパス環境が
   変わり、鉛直の変化と区別がつかなくなります
4. 電源を入れ、**最低15分**放置してから始める。コールドスタート直後の収束を
   実験データに混ぜないためです（`data/samples/qz1-dorm-walk-20260706.txt` の
   最初の数百エポックがまさにそれです）
5. fix が安定していること、衛星数が妥当であることを画面で確認

### 1.3 設定

`設定` → `QZ1測量` → **QZ1 水位実験** カード。

| 項目 | 初回の推奨 | 備考 |
|---|---|---|
| 実験ID | `vertical-displacement-001` | 後で再解析するときの鍵になります |
| 段階 | 固定治具 | |
| 受信機 | QZ1 / QZ1LE | 実際に使う方 |
| 基準高さ | `0, 10, 20, 30, 50, 100` | mm |
| 滞在時間 | **120 秒** | 下記1.6参照 |
| 整定時間 | 15 秒 | 移動直後を捨てます |
| 許容誤差 | 10 mm | 「測定できた」と呼ぶ基準。設計判断であって物理定数ではありません |
| 復路も測る | ✅ | ドリフトの確認に必要です |

`0,10,20,30,50,100` を復路つきで回すと 11 段 = 移動時間を除いて 22 分です。
移動時間を入れて **30〜40 分**を見てください。

### 1.4 実行

1. 「QZ1に接続」でシリアルを開く（上の「圃場を測る」カードと同じ接続です）
2. 「実験を開始」
3. カードが「いま置くべき高さ」を出します
4. **受信機をその高さに移動させ**、動きが完全に止まってから
5. 「**位置に到達**」を押す — **押した瞬間から**滞在時間が数え始めます
6. 滞在中は**受信機・治具・自分の体に触れない**。人体は GNSS 信号を遮ります。
   最低でも 2〜3 m 離れ、アンテナと空の間に立たないこと
7. 残り時間が 0 になると自動的に次の段へ進みます
8. 全段終了まで 3〜7 を繰り返す

途中で何かあったら「中止」。**取得済みデータは消えません。**

### 1.5 記録すること（ソフトウェアが取らないもの）

`notes` に必ず:

* 日時・場所・天気（特に雲量と降雨）
* 周囲の遮蔽物（建物・木・車）とおおよその方位
* 使った基準ブロックの**実測値**
* 実験中に起きたこと（人が横切った、車が停まった、雨が降り出した）
* 浮体側なら水温・風

これらは後から復元できません。

### 1.6 滞在時間について

**60 / 120 / 300 秒に「正解」はありません。** ソフトウェアはどれも仮定していません。

判断材料: 解析が `INSUFFICIENT` で「相関が強すぎる。独立なサンプルが実質 N 件」と
出た場合、**滞在時間を延ばす**のが唯一の対処です。フィルタでは解決しません
（平滑化はむしろ相関を上げ、有効サンプル数を下げます）。

`experiments/qz1-water-level/configs/long-dwell-300s.json` は、高さを 0/50/100 に
減らして滞在を 300 秒にした設定です。全体時間を増やさずに1段あたりの情報量を
増やせます。

### 1.7 解析

カードで「解析する」。フィルタは **`none` から始めてください。**
生データが何を言っているかを先に見ます。

その上で:

| プリセット | 内容 |
|---|---|
| `none` | 無加工。最初に見るべきもの |
| `valid-fix-only` | 標高があり fix が有効なものだけ |
| `standard-quality-gate` | ＋ 衛星5以上、HDOP 3以下、MAD 3σ 外れ値除去 |
| `quality-gate-then-median-15` | ＋ 15サンプル移動中央値 |

**結果が良くなるまでフィルタを変えるのは、実験ではありません。** 使った鎖は
必ず結果と一緒に記録され、レポートに印字されます。複数の鎖を試すのは構いません
が、**全部報告してください**。都合の良い一つだけを残さないこと。

### 1.8 保存

「CSV・メタデータを保存」で3ファイルが出ます。

```text
<実験ID>.csv           1 fix = 1行。生NMEAセンテンス込み
<実験ID>.meta.json     設計（高さ・滞在・整定・許容誤差）
<実験ID>.marks.json    どの時刻にどの高さだったか
```

`experiments/qz1-water-level/data/` に置いてください。**このディレクトリは
`.gitignore` されています** — GNSS記録は正確な位置情報であり、機微な情報として
扱います。共有する場合は中身を見てから `git add -f` で明示的に。

「レポート(HTML)」は図つきの自己完結ファイルです。外部リソースを一切参照しない
ので、そのまま添付・保存できます。

### 1.9 オフライン再解析

```bash
node experiments/qz1-water-level/scripts/analyze-experiment.mjs \
  --nmea experiments/qz1-water-level/data/run-001.nmea \
  --marks experiments/qz1-water-level/data/run-001.marks.json \
  --config experiments/qz1-water-level/configs/vertical-displacement-001.json \
  --filter standard-quality-gate \
  --html experiments/qz1-water-level/data/run-001.report.html
```

保存済みCSVからも同じことができます。

```bash
node experiments/qz1-water-level/scripts/analyze-experiment.mjs \
  --csv experiments/qz1-water-level/data/run-001.csv \
  --config experiments/qz1-water-level/configs/vertical-displacement-001.json
```

終了コードは、1つ以上の段差が測定できたとき `0`、どれも測定できなかったとき `2`
です。`2` はエラーではありません — 有効な負の結果です。

> **オフライン経路のマークは GNSS UTC で書いてください。** ライブ実行が書き出す
> マークはホスト時計です。ロガーアプリで別途記録したログを解析する場合は、
> マークの時刻がログの RMC/ZDA と同じ時系であることを確認してください。

## 2. 判定の読み方 / Reading the verdicts

| 判定 | 意味 |
|---|---|
| **PASS** | 基準位置と95%信頼区間が分離し、誤差が許容内で、往復で再現した |
| **INCONCLUSIVE** | 分離はした（**変化は検知できた**）が、大きさが合わない・符号が逆・往復で食い違う |
| **FAIL** | 基準位置と信頼区間が重なる。**この段差を雑音と区別できない** |
| **INSUFFICIENT** | 判定に足るデータがない。サンプル数不足か、相関が強すぎて独立な測定が2件に満たない |

**INCONCLUSIVE は PASS の弱い版ではありません。** 「検知」と「測定」は別の主張で、
このプロジェクトに必要なのは後者です。+30 mm の移動に対して毎回 +180 mm と
言う受信機は、段差を検知していますが測定はしていません。

次のような結果は**正当な成果**です。

```text
10 mm   FAIL
20 mm   FAIL
30 mm   INCONCLUSIVE
50 mm   PASS
100 mm  PASS
```

### 信頼区間の読み方

レポートの `±95%CI` は AR(1) の有効サンプル数で補正済みですが、**それでも楽観的**
です。GNSS誤差の相関はラグ1より長く続きます。**不確かさの下限**として読んでください。

`ci95Naive`（素朴な sd/√n）も内部には残してあります。両者の差が、独立性の仮定が
どれだけ嘘かの目安です。

### ヒステリシス

同じ高さの往路と復路の差です。大きければ、実験中に標高がドリフトしていて、
上の「変位」の一部は**移動ではなく経過時間**です。これが許容誤差を超えると、
PASS は INCONCLUSIVE に格下げされます。

## 3. 第2段階: 浮体実験 / Floating-ball experiment

第1段階の後にのみ意味があります。

### 3.1 場所

透明な水槽または水位を制御できる容器。屋外の実圃場より、まず制御された環境で。

* 水位を既知量だけ変えられること
* **水位を独立に実測できること**（水位標、フックゲージ、目盛付き定規）
* 浮体が自由に動ける広さ
* 空が開けていること

### 3.2 手順

1. [HARDWARE.md](HARDWARE.md) の浮体を設置し、係留する
2. **最低水位のとき**にケーブルが張っていないことを確認する。張っていたら弛みを増やす
3. 実験前に浮体の質量を測る（泥・水の付着による変化を後で見るため）
4. 水位実測用の基準を設置し、**GNSSとは独立に**読めるようにする
5. カードの段階を「浮体ブイ」にする。基準高さは**実測した水位**です
6. 滞在時間は第1段階より長く（推奨 300 秒）。波の周期を平均するためです
7. 水位を既知量だけ変え、**波が収まってから**「位置に到達」を押す
8. 記録: 実測水位・GNSS標高・時刻。3つ全部です

### 3.3 この段階が暴くもの

第1段階との差が、以下の合計です。

* 浮体の運動（波・風）
* ケーブルの引き（張ったか、泥に絡んだか）
* 浮力の変化（泥・水の付着による喫水変化）
* アンテナの傾き
* 水面のマルチパス
* GNSSノイズ（第1段階で測った分）

**第1段階より悪くなるのが普通です。** どれだけ悪くなるかが、この段階の成果です。

### 3.4 記録すること

* 実測水位の**測り方とその不確かさ**（比較は基準の精度を超えられません）
* 水面の状態（静穏／さざ波／波）
* 風向・風速
* 実験前後の浮体質量
* ケーブルの張り具合（目視で構いません。「たるんでいた」「時々張った」）

## 4. 較正 / Calibration

較正は**実験が裏付けた後にのみ**有効になります。

```text
H(t) = H0 + (Z(t) - Z0)

Z0 = 較正時のGNSS標高
H0 = そのときに実測した水深
```

較正レコードには、時刻・機器ID・**それを裏付けた実験ID**と判定結果が入ります。
`calibration.js` は次の場合に水深の算出を**拒否**します。

* 較正に紐づく検証実験がない
* その実験でどの段差も測定できなかった（`resolvedStepMm === null`）
* 要求分解能が実証済み分解能より細かい（50 mm しか実証していないのに 10 mm を求める）
* 較正が古い（既定 24 時間。**根拠のない暫定値です** — ドリフトの実測がまだないため、
  安全側に短く置いてあります。実測後に見直してください）

画面は3つを常に別行で出します。

```text
① 生のGNSS標高      42.347 m
   基準（0mm）の標高  42.315 m
② 相対変位          +32 mm      ← 水深ではありません
③ 較正済み水深       表示できません
   （較正に紐づく検証実験がありません）
```

**`水深 = 29 mm` と表示してよいのは③の条件が満たされたときだけです。**
