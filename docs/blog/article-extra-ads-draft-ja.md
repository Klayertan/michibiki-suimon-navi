## はじめに

**本記事は、さくらのクラウド検定 学生アンバサダーとして執筆しています。**

こんにちは。学生エンジニアです。

本編（#1 サーバー、#2 画面の公開、#3 データを受け取るAPI）とは別に、今回は**番外編**です。テーマは、**「スイスイナビに広告を載せるには、何が必要か」**。

理由は2つあります。ひとつは、広告の仕組み（広告ネットワーク、同意、プライバシー）を、実際に手を動かして**学びたい**から。もうひとつは、正直に言うと、**少しでも収益になるか試したい**からです。

ただ、スイスイナビは、農家さんが圃場（ほじょう）で使う道具で、ドローンを飛ばす画面もあります。広告で使いにくくなっては本末転倒です。そこで、**迷惑にならない作り方**を先に決めてから作りました。

> 広告を、**邪魔にならない場所**に、**何が起きるかを隠さずに知らせたうえで**出せる状態にする。ドローンの画面には、**絶対に出さない**。

なお、この設計は途中で一度変わりました。最初は「同意をもらった後にだけ出す」で作り、そのあと、**「出す場所では、どなたにも出す。そのかわり、隠さず知らせる」**に変えました。変えた理由と、まだ残っている宿題は、「同意をたずねるか、知らせるだけか」の節に書きます。

そして、**うまくいくか分からない部分（広告ネットワークの審査）も、結果が出たら書きます。** 審査は、国の設定をやり直したあとの**2026年10月12日**にリクエストしました（最初のアカウントでは、10月11日にリクエストしていました）。今の時点では、結果はまだ出ていません。

## 先に用語を整理

| 言葉 | ひとことで |
|---|---|
| 広告ネットワーク | サイトの持ち主と、広告を出したい会社をつなぐ仕組み。サイト側は広告を置く場所を用意し、クリックや表示に応じて報酬がもらえる |
| Google AdSense | Googleの広告ネットワーク。申し込んで審査に通ると、広告を出せる |
| パブリッシャーID | AdSenseの「自分の登録番号」。`ca-pub-` のあとに16桁の数字が続く。ページのソースに載るので、秘密ではない |
| 広告ユニット（スロット） | 「ここに広告を出す」という枠ひとつひとつ。枠ごとに10桁くらいの番号（スロットID）が付く |
| Cookie | ブラウザに残る小さなメモ。広告では、同じ人かどうかを見分けるのに使われることがある |
| 同意（コンセント） | 「広告のために、あなたのブラウザの情報を取得してよいですか？」に、訪問者が答えること |
| 同意管理ツール（CMP） | 同意をたずねて、答えを記録する部品。AdSenseには、Googleが認定した、無料で使えるものがある |
| 外部送信規律 | 日本の電気通信事業法の決まり。サイトが訪問者の情報を外へ送るとき、**何を・誰に・何のために**送るかを、公表（または通知）する。私の理解では、同意までは求めていない（専門家の意見ではありません） |
| アフィリエイト | 商品やサービスを紹介して、そこから買われたら報酬をもらう仕組み。バナー（画像つきのリンク）で置くことが多い |
| `rel="sponsored"` | 「このリンクは広告です」と、検索エンジンに伝えるためのリンクの印 |
| 審査 | 広告を出す前に、広告ネットワークがサイトをチェックすること。通らないと広告を出せない |

## 広告を入れると、何が変わるのか

スイスイナビは、これまで「**データは端末の中にだけ**ある」アプリでした。広告を入れると、広告を配信する会社との通信が増えます。つまり、アプリの性質が少し変わります。だから、次の約束を最初に決めました。

1. **初期状態はオフ。** 設定ファイルで `enabled: false` のとき、広告のためのコードは読み込みさえしない。
2. **何が起きるかを、広告のすぐ横から読めるようにする。** 「広告」のラベルの横に「広告について」のリンクを置いて、プライバシーページにつなぐ。
3. **ドローンの画面には出さない。** 設定ファイルに書いても出さない。
4. **オフラインのときは出さない。スマホ（画面が狭いとき）は、置き場所を変えて、1か所だけ出す。**
5. **「広告」と書く。** ほかのボタンから離して置く（間違えて押さないように）。
6. **何が送られるかを書いたページ（プライバシーページ）を用意する。** 広告の事業者名、取得されうる情報、目的を書く。

## どこに置くか

置き場所の候補は、3つありました。

- **基本モードの画面の下の帯**：見られる回数は増えるけれど、地図の画面がごちゃつく。
- **設定画面の中**：邪魔にはならないけれど、ほとんど誰も開かないので、収益はほぼ期待できない。
- **画面の上の真ん中**：タイトルとボタンの間にあいている場所。いつも見えて、地図の邪魔にならない。

3つ目にしました。タイトルと「使い方」ボタンの間の空きが、ちょうど320×50ピクセル（標準的な小さいバナーの大きさ）に収まります。

ただし、ボタンのすぐ近くに広告があると、間違えて押されやすくなります（広告ネットワークも嫌がります）。そこで、**左右に24ピクセルずつ空け**、**「広告」というラベルと、「広告について」のリンク**を付けました。また、横幅981ピクセル未満（スマホなど）では、ヘッダーに置く場所がありません。スマホは、圃場で使う人が多い機器なので、最初は「出さない」つもりでした。でも、見られる回数が減ってしまうので、あとから**地図と最初のカードのあいだ**にも置けるようにしました（次の「スマホにも出す」を参照）。

## 作り方

### 1. 設定ファイル（最初はオフ）

広告の設定は、1つのファイル `config/ads-config.js` に集めました。出荷時の状態は、次のとおりです。

```
window.SUISUI_ADS_CONFIG ??= {
  enabled: false,          // オフ
  provider: null,          // "adsense" か "banner"
  modes: ["basic"],        // 出してよい画面（ドローンは書いても無視される）
  consent: "notice",       // "notice"＝全員に出して、リンクで知らせる / "optin"＝同意の後だけ
  mobile: true,            // スマホの幅でも、1か所だけ出す
  privacyUrl: "",          // プライバシーページ（広告を有効にするなら必須）
  adsense: { client: "", slot: "" },
  banners: []
};
```

このファイルは**訪問者全員のブラウザに届く**ので、入れてよいのは公開してよい番号だけです（パブリッシャーIDとスロットID、バナーの画像とリンク）。パスワードやAPIキーは入れません。

### 2. 「出すか、出さないか」を決める部品

「いま広告を出してよいか」を決める部分は、画面と切り離して、**入力を渡すと答えが返るだけの小さな部品**にしました。画面の操作が入らないので、テストが書きやすいからです。

答えは、次の順番で決まります。

1. 設定が不完全 → 出さない
2. ドローンなど、出さない画面 → 出さない
3. 画面が狭い → スマホ用の設定（`mobile`）がオフなら出さない。オンなら、同じルールで判断する
4. オフライン → 出さない
5. 設定が「お知らせ型（`notice`）」 → **出す**（たずねない）
6. 「同意型（`optin`）」で、訪問者が「同意した」 → 出す
7. 同意型で、訪問者が「断った」 → 出さない（二度と聞かない）
8. 同意型で、まだ答えていない → 出さない。**ただし、ここまでの条件がすべて満たされているときだけ**、同意をたずねる

1〜4番は、お知らせ型でも同意型でも、先に効きます。つまり、**お知らせ型でも、ドローンモード・オフライン・出さない画面では出ません**。8番の「ここまでの条件がすべて満たされているときだけ」も大事です。出せない画面で、同意だけをたずねるのは、意味がなく、迷惑だからです。

この部品には、**26個のテスト**を書きました。たとえば「ドローンの画面は、設定に書いても、同意があっても、出さない」「AdSenseの番号は、形が違うものは捨てる」「バナーのリンクは `https` だけ。`javascript:` は捨てる」「同意の保存場所が使えなくても、エラーにならず、勝手に『同意した』扱いにもならない」「お知らせ型でも、ドローン・オフライン・出さない画面では出ない」などです。

### 3. 画面に出す部分

実際に画面に広告を出す部分は、別のファイルにしました。ここでは、次のことを守っています。

- **1つの枠につき、一度だけ**広告を描く。画面を切り替えるたびに読み込み直すと、広告ネットワークから「更新しすぎ」と見られかねないから。
- **バナー**は、ただのリンクと画像（`<a rel="sponsored"><img>`）。第三者のプログラムは読み込まない。
- **AdSense**は、広告を出すと決まったときにだけ、広告のプログラムを読み込む。
- お知らせ型では、枠に「**広告について**」のリンクを出す。同意型では、かわりに「広告の設定」ボタンを出す（同意を取り消すため）。

![開いた直後の画面（お知らせ型）。上の真ん中に、「広告」のラベルと「広告について」のリンクつきで、サンプルのバナーが出る（320×50。表示テスト用の画像で、本物の広告ではない）。同意バナーは出ない](media:ads-08-notice-mode-header-ad.jpg)

### 4. プライバシーページ

広告のことを知らせる場所として、プライバシーページ `privacy.html` を書きました。書くために、**このアプリが今、外のどこと通信しているか**をコードから洗い出したところ、広告とは関係なく、次の通信がありました。

- 地図の画像：OpenStreetMap、国土地理院
- 画面の部品：unpkg、jsDelivr
- 天気：Open-Meteo（「気象を自動取得」を使ったときだけ。**圃場や現在地の緯度・経度を送って**、雨量などを受け取る）

「データは端末の中だけ」と思っていましたが、**天気を取るときは、位置を外に送っていました。** 広告を入れる準備をしていて、広告より前に、自分のアプリの説明が足りていなかったことに気づきました。

「広告について」の部分には、広告の配信事業者（Google AdSense）、取得されうる情報（IPアドレス、Cookie、ブラウザの種類など）、目的（広告を表示し、その効果を測る）、**圃場データや位置情報は、広告の事業者へ送らない**こと、ドローンモードとオフラインでは出さないこと、Googleの広告設定へのリンクを書きました。

![プライバシーページの「広告について」。広告を、どなたにも表示すること、何を取得されうるか、いつ出さないかを書いた](media:ads-10-notice-mode-privacy-ads-section.jpg)

### 同意をたずねるか、知らせるだけか

最初は、**同意型**で作りました。広告を出せる状態で、まだ答えがないときだけ、画面の下に小さな同意バナー（「同意する」「断る」）を出します。「同意する」を押すまでは、広告のための通信を一切しません。確かめると、答える前の通信は0件でした。

![最初に作った同意バナー。広告を出せる状態で、まだ答えていないときだけ、画面の下に出る。この時点で、広告のための通信はまだしていない（今も部品として残してあるが、公開する設定では使わない）](media:ads-01-consent-bar-before-any-ad-request.jpg)

でも、これだと、**「断る」を押した人には、広告がずっと出ません**。広告は、置く場所を自分で決めて、見てもらうためのものです。そこで、**訪問者に出すかどうかを選んでもらう作りをやめて、「出すと決めた場所では、どなたにも出す。そのかわり、隠さず知らせる」**ことに決めました。

- 広告の横に、「広告について」のリンクを置く（プライバシーページにつながる）。
- 同意バナーは出さない。
- 変えるのは、設定ファイルの `consent` の1行と、判断の部品の1か所だけ。**同意型の部品も、消さずに残してある**（今後、同意が必要な場面で使えるように）。

ここで、**日本の話と、海外の話を分けておく必要があります。**

- **日本：** 私が調べた範囲では、電気通信事業法の「外部送信規律」は、外へ送られる情報を**公表・通知**することを求めるもので、同意までは必須とされていない、という理解です。お知らせ型は、これに合わせた作りです。（法律の専門家の意見ではありません。）
- **EU・英国・スイス：** Googleの方針では、これらの地域の訪問者に広告を出すときは、**Googleが認定した同意管理ツール（CMP）**が必要です。AdSenseの「プライバシーとメッセージ」に、無料で使えるものがあります。**これは、下書きまで作りました（下の画面）。** 公開（Publish）は、広告を有効にする日にします。Googleの説明では、AdSenseのコードをサイトに置いたうえでメッセージを公開する、という順番だからです。

つまり、いま正直に言える状態は、「**日本の訪問者には、お知らせ型で出せる。EU・英国・スイスの訪問者には、Googleの同意メッセージを下書きまで作った。公開は、広告を有効にする日**」です。

**作るときにやったこと（AdSenseの画面。すべて自分の手で操作した）**

1. 「プライバシーとメッセージ」→「European regulations」で、メッセージを作る。サイトは `suisuinavi.sakura.ne.jp` を選ぶ。
2. **サイト名・プライバシーポリシーのURL・ロゴ**を入れる。この3つが足りないと、公開のボタンが押せない（赤い帯で「missing logo」などと出る）。ロゴは、アプリの画面の左上にある緑の「水」の四角を、画像にして使った。
3. **「同意しない（Do not consent）」のボタンを、すべての国でオン**にした。画面には「同意率が下がるかもしれない」と出る。それでも、同意と同じくらい押しやすい「同意しない」を置くほうが安全だと考えた（私の判断で、法律の専門家の意見ではない）。収益への影響は、見る人が日本中心なので小さいはず。
4. 「設定（Settings）」のタブも読んだ。広告のパートナー（198社の標準リスト）などは、**初期値のまま**にした。

![AdSenseで作った、EU・英国・スイス向けの同意メッセージ（下書き）。サイト名、ロゴ、「同意しない」「同意する」「オプションを管理」の3つが並ぶ。右はその設定](media:ads-11-eu-consent-message-draft.jpg)

なお、メッセージの文面に「0 partners（0社）」と出ていましたが、これは下書きの間だけの表示で、公開すると、設定のパートナーの一覧が入る、というGoogleの説明でした（公開後の画面は、まだ確かめていません）。

### スマホにも出す

「スマホでは出さない」にしていましたが、実際に使うのはスマホが多いはずなので、出せるようにしました（`mobile: true` のときだけ）。置き場所は、スマホの画面を見て決めました。上のヘッダーは、タイトルとボタンで、もういっぱいです。地図の上に置くと、地図が狭くなります。そこで、**地図と、いちばん上のカードのあいだ**にしました。

- ページの流れの中に置くので、下にスクロールすると、**広告は流れて消える**（画面にくっついて残らない）。
- 地図の操作ボタンの上には、重ならない。**地図の高さも変わらない**（390ピクセルのまま）。
- 「広告」というラベルと、「広告について」のリンクを付けた。
- お知らせ型なので、開いてすぐ出る。同意バナーは出ない。ドローンモードでは出ない。

広さが足りる画面（横幅981ピクセル以上）は、これまでどおり、ヘッダーに出ます。**どちらか一方の枠だけ**を使います。

![スマホの幅（375ピクセル）。開いてすぐ、地図の下に、「広告」のラベルと「広告について」のリンクつきで、320×50のサンプルが出た](media:ads-09-notice-mode-mobile-ad-below-map.jpg)

## 動かして確かめた

本物の広告はまだ出せないので、**表示テスト用のサンプルのバナー**を一時的に設定して、自分のMacで動かして確かめました（確かめたあと、設定は元に戻しました）。

| 場面 | 期待 | 結果 |
|---|---|---|
| 開いた直後（お知らせ型） | 上の真ん中に、「広告」と「広告について」つきで出る。同意バナーは出ない | そのとおり。高さも増えなかった |
| ドローンモードにする | 広告が消える | 消えた |
| 基本モードにもどす | 広告がまた出る。画像が増えない | 1枚のまま（再読み込みなし） |
| スマホの幅（375ピクセル） | 開いた直後に、地図の下に1か所だけ出る。地図の高さは変わらない。同意バナーは出ない | そのとおり（地図は390ピクセルのまま。横にはみ出さない） |
| スマホで、ドローンモードにする | 広告が消える | 消えた（基本モードにもどすと、同じ広告がもう一度出る。画像は増えない） |
| 設定を同意型（`optin`）にする | 答えるまで、広告のための通信をしない。同意バナーが出る。「同意する」で広告が出る | そのとおり（答える前の広告の通信は0件） |
| 出荷時の設定（オフ） | 広告のコードを、読み込みさえしない | 読み込まれなかった |

確かめ方は、ブラウザの開発者向けの機能で、通信の一覧を見ました。「広告の画像を取りに行く通信」が、**出してはいけない場面（ドローンモード、オフライン、同意型で答える前）で、一度も出ていない**こと、そして、出す場面でも**1つの枠につき1回だけ**であることを見ています。

## AdSenseに申し込む

広告ネットワークは、まず**Google AdSense**を試しました。広告の中身を自分で探さなくても、サイトに合う広告を自動で選んでくれるからです。

**先に調べて分かったこと**

- 申し込めるのは**18歳以上**。サイトのHTMLを自分で触れること、内容が**独自で役に立つ**ことが求められる（Google公式）。
- サイトの確認方法は**3つ**：AdSenseのコードをページに貼る／`ads.txt` というファイルを置く／**メタタグ**を貼る。メタタグは、広告のコードをトップページに置きたくないとき向け（Google公式）。今回は、広告のコードを、ドローンモードを含む**すべての画面で読み込むことになる**のを避けたいので、**メタタグと `ads.txt`** を使いました（広告のコードは、広告を出すと決めたときだけ読み込みます）。
- **承認されるまでは、広告を出せない。** 審査は、数日、長いと2〜4週間（Google公式）。
- **さくらの `*.sakura.ne.jp` のような、共有のアドレスでも通るか**は、Googleの公式ページでは**確認できませんでした**。解説記事（Xserverやお名前.comなど）には、「独自ドメインが必須」と書かれています。これは、私は確かめていない情報です。

だから、**試してみないと分からない**ことでした。

**実際にやったこと（1回目：2026年10月11日。あとで閉じることになったアカウント）**

1. **登録する。** Googleアカウントで、AdSenseに登録しました。サイトのアドレスの欄に `suisuinavi.sakura.ne.jp` を入れると、そのまま受け付けられました。続く画面に、やることが3つ出ます：お支払い情報（必須）、広告の見え方を見る（任意）、サイトをAdSenseにつなぐ（必須）。お支払い情報は、個人の情報を入れる画面なので、この記事には載せません。

![登録後の画面。3つのカードが出る。サイトのアドレスは、そのまま受け付けられた](media:adsense-02-onboarding.jpg)

2. **メタタグを確認する。** 「サイトをつなぐ」で、確認の方法に「メタタグ」を選ぶと、Googleが貼るべき1行を見せてくれます。パブリッシャーID（`ca-pub-` と16桁の数字）が入っています。

![Googleが見せたメタタグ。この1行を、ページの `<head>` の中に入れる](media:adsense-03-verify-meta-tag.jpg)

3. **アプリに入れる。** そのタグを、アプリの `index.html` の `<head>` に入れました。このタグは「このサイトの持ち主は、このアカウントです」という宣言だけで、広告のプログラムを読み込まず、通信もしません。また、`ads.txt` というファイルも置きました。Google公式の形式の1行で、「このサイトの広告は、この番号の人が出してよい」と宣言するものです（`google.com, pub-…, DIRECT, f08c47fec0942fa0` という形）。置き場所は、サイトの一番上のアドレス `https://suisuinavi.sakura.ne.jp/ads.txt` です。

4. **公開する。** 変えたファイルをzipにまとめ、サーバーのファイルマネージャーでアップロードして、サーバーの上で解凍しました。そのあと `curl` で、メタタグも `ads.txt` も、ほんとうに公開されていることを確かめました。広告の設定は、まだオフのままです。

![公開用のフォルダー。ads.txt が増え、index.html が新しくなった](media:adsense-04-files-unpacked-ads-txt.jpg)

5. **確認を押す。** AdSenseの画面で「メタタグを置いた」にチェックを入れて「確認」を押すと、**所有の確認が通りました**。共有のアドレスでも、ここまでは進めました。

![「サイトの所有確認」に緑のチェック。下に「審査をリクエスト」が出た](media:adsense-05-ownership-verified.jpg)

6. **プライバシーページを仕上げてから、審査をリクエストする。** 審査の人が見るのは、公開されているサイトです。そこで、プライバシーページの運営者名・連絡先などを埋めて公開し、アプリの「使い方」の画面にリンクを付けてから、「審査をリクエスト」を押しました。画面は、「サイトを広告の表示に向けて準備中（Getting ready）」に変わりました。

![審査をリクエストした直後の画面。所有確認と審査リクエストの両方に緑のチェック](media:adsense-06-review-requested.jpg)

**公開したあと、確かめたこと**

`curl` で、プライバシーページ（200）、メタタグ、`ads.txt`、そしてアプリ本体がふつうに動いていること、広告の設定がオフのままであること、ブログに影響がないことを確かめました。アップロードに使ったzipは、削除して、ダウンロードできない（404）ことも確かめました。

### 国をまちがえて、作り直した（2026年10月12日）

審査のリクエストまで進んだあと、**お支払いのための本人確認（電話番号）**で止まりました。電話番号の確認は、**アカウントの国の番号しか受け付けません**。私のアカウントは、**マレーシア**になっていました。思い返すと、登録の最初の画面で、利用規約がマレー語で出ていたのが、そのしるしでした。日本の電話番号は断られ、マレーシアの番号でも「コードを送れません」「何度も試しすぎました」と出て、先に進めませんでした。

そこで調べると、Googleの公式ページに、**AdSenseでは、お支払い先の国を変えられない**こと、国が変わる場合は**今のアカウントを閉じて、新しく作る**ことが書かれていました。受け取りは日本の銀行なので、閉じて作り直すことにしました。

1. **アカウント情報のページで「アカウントを閉じる」を押す。** 選べるアカウントが2つ（AdSenseと、使っていないYouTube用）出たので、両方を選びました。YouTubeで収益を得ている場合は、閉じると収益が止まるので、この操作は注意が必要です。
2. **同じGoogleアカウントで、もう一度登録する。** 利用規約の下の「国・地域」を**日本**にすると、規約が日本語になりました。
3. **新しい番号（`ca-pub-…`）に、メタタグと `ads.txt` を直して公開する。** 古いアカウントの番号は、サイトから消しました。
4. **所有確認 → 審査をリクエストする。** 1回目と同じ流れです。

![古いアカウントを閉じた画面。「アカウントを閉じました」と出る](media:adsense-07-old-account-closed.jpg)

![新しいアカウントでGoogleが見せたメタタグ。番号が新しくなっている](media:adsense-08-new-account-meta-tag.jpg)

![新しいアカウントで、サイトの所有確認が通った](media:adsense-09-new-account-ownership-verified.jpg)

![新しいアカウントで、審査をリクエストした直後の画面](media:adsense-10-new-account-review-requested.jpg)

作り直しにかかったのは、約1日分の手間でした。1回目のアカウントのタグも審査のリクエストも、無駄になりました。でも、**サイトの準備（プライバシーページ、`ads.txt` を置く場所、公開の手順）は、そのまま使えました**。変えたのは、番号だけです。

## 結果

審査は、1回目を **2026年10月11日**、作り直したあとのアカウントを **2026年10月12日** にリクエストしました。いまの審査の対象は、作り直したあとのアカウントです。AdSenseの画面は「広告を表示する準備中（Getting ready）」です。

なお、AdSenseのサイト一覧には、「ads.txt の状態：見つかりません」と出ています。`ads.txt` は、公開サイトに置いてあって、中身も正しいことを `curl` で確かめました。Googleがまだ読みに来ていないだけなのか、それとも `sakura.ne.jp` という、自分のものではないドメインの一番上を探しているのか、私には分かりません。審査には関係しないようですが、変わるかどうかを見ておきます。

**審査のリクエストのときに公開していたプライバシーページは、まだ「同意をたずねる」型で書いた版でした。** お知らせ型に直した版は、まだ公開していません（広告を有効にするのと一緒に公開します）。

## つまずいたこと

**① このMacには、Node.jsが入っていなかった**

スイスイナビのテストは `npm test`（Node.jsで動く）で動かす決まりですが、このMacにはNode.jsが入っていませんでした。そこで、macOSに最初から入っているJavaScriptの実行環境（JavaScriptCore）で、テスト用の小さな代用品を作って、26個のテストを動かしました。**公式のテストコマンドでは、まだ動かしていません。** 近いうちに、Node.jsが入っている環境で動かして確かめます。

**② 「見えない画面でも、広告を読み込んでしまう」ところだった**

最初の設計では、「画面が狭いときは、広告の置き場所を消す」ことしか考えていませんでした。でもそれだと、**見えない広告を、裏で読み込んでしまう**（誰にも見られない広告の通信が発生する）ことに気づきました。そこで、「画面が狭い」を、判断の条件に足しました。スマホ用の枠を作ったあとも、**今の画面で使わない方の枠は、読み込まない**ようにしてあります。

**③ プライバシーページが、公開の対象に入っていなかった**

自動デプロイ（GitHubからさくらのサーバーへファイルを送る仕組み）は、決まったファイルとフォルダーしか送りません。新しく作ったプライバシーページは、その中に入っていませんでした。このままだと、広告の横の「広告について」のリンクが「見つからない」になります。今回は、公開用のzipに入れて、手でアップロードして解決しました。自動デプロイの設定は、まだ直していません（`privacy.html` と `ads.txt` を送る対象へ足す必要があります）。

**④ アプリの説明が、足りていなかった**

前の節に書いたとおり、天気のために位置を外へ送っているのに、そのことをどこにも書いていませんでした。プライバシーページを書いて、初めて気づきました。

**⑤ 「確認」は、公開されたサイトを見に来る**

Googleの「確認」は、インターネット上の公開サイトにメタタグがあるかを見に来ます。自分のMacで直しただけでは通りません。先に公開して、`curl` で確かめてから、「確認」を押す順番にしました。

**⑥ スマホの広告の枠が、高さ345ピクセルになった**

スマホ用の枠を最初に画面に出したとき、枠が**縦に345ピクセル**も広がって、下のカードが画面の外に押し出されました。原因は、横並びの枠のために書いた指定（`flex: 0 1 320px`）が、**縦に並べる枠の中では「高さ320ピクセル」と読まれた**ことでした。スマホ用の枠には、横幅320・高さ50を、そのまま書き直して直しました（高さは、広告のラベルを含めて約75ピクセルになりました）。同じ指定でも、並べる向きで意味が変わることを、画面を見て初めて気づきました。

**⑦ AdSenseの「国」を、まちがえた**

登録の最初の画面で、利用規約がマレー語で出ていた時点で、国が日本になっていないことに気づくべきでした。国は、**あとから変えられません**。実際に気づいたのは、電話番号の確認で、日本の番号を断られたときでした。そのため、アカウントを閉じて作り直すことになりました。

**反省：** お金に関わる設定のうち、**あとから変えられないもの**は、入力の前に一度立ち止まって見る。今回は、「国・地域」でした。

**⑧ 同意型で作り終えたあとに、設計を変えた**

同意をたずねる作りで、テストも画面も最後まで作ってから、「どなたにも出す」に変えました。無駄にならなかったのは、「出すか出さないか」を決める部分を、画面から切り離していたからです。変えたのは、設定の1行（`consent`）と、判断の1か所、広告の横のリンク、プライバシーページの文章でした。ただし、**変えたあとに、EU・英国・スイス向けの同意ツールという宿題が残りました**（前の節。下書きまでは作りました）。日本向けの説明だけで、全世界の訪問者に出してよいわけではありません。

## 学んだこと

- **広告は、足す前に「やらないこと」を決める。** 出さない画面、知らせ方、オフが初期値。
- **決める部分は、画面から切り離すと、テストで守れる。** 「ドローンには出さない」を、テストで固定できた。
- **通信の一覧を見て、確かめる。** 「ドローンモードでは通信しない」「出すのは1枠1回」は、気持ちではなく、一覧で確かめる。
- **同意をたずねるか、知らせるだけか。国によって決まりが違う。** 日本は公表・通知が基本、EU・英国・スイスはGoogleの同意ツールが必要（下書きまで作った。公開は広告の日）。広告を出す場所を自分で決めるなら、そのかわり、隠さず知らせる。
- **設計は、あとから変わる。** 判断の部品を分けておいたので、変えるのが小さくて済んだ。
- **広告の準備は、自分のアプリの棚卸しになる。** 何をどこへ送っているかを、初めて全部書き出した。
- **確認は、公開してから。** 自分の手元で直しただけでは、外の人には見えない。
- **あとから変えられない設定は、最初に見る。** AdSenseの国は、変えられない。気づくのが遅いと、作り直しになる。
- **同じCSSでも、並べる向きで意味が変わる。** 画面を見て確かめないと、気づけなかった。
- **作り直しになっても、準備は使い回せる。** プライバシーページや公開の手順は、そのまま使えた。変えたのは番号だけ。
- **共有のアドレスでも、所有確認までは進めた。** ただし、審査に通るかは別の話。
- **審査は、通るとは限らない。** その結果も、記事の一部。
