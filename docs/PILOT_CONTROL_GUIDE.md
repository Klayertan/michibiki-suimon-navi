# 低速操縦ガイド / Pilot control guide

キーボードを仮想スティックとして使い、**極めて低速で**機体を動かすための機能です。

> **これは RC 送信機の代わりではありません。**
> 低速テスト専用です。送信機は常に手元に置き、いつでも MANUAL/STABILIZE に
> 切り替えて手動で引き継げる状態で運用してください。
>
> **This is not a replacement for an RC transmitter.** It is a low-speed test
> facility. Always keep the transmitter in your hands and stay ready to take
> over manually.

この機能は:

* **アームしません。** 離陸も着陸も RTL もしません。フライトモードも変えません。
* 既定で**無効**です。`SUISUI_MAVLINK_ALLOW_PILOT_CONTROL=1` で起動したときだけ有効になります。
* 機体が**自分でアームされ、GUIDED モードにある**ときにだけ実際に動きます。
  そうでなければ指令は送られますが ArduPilot が無視します（そして UI が理由を表示します）。
* ArduPilot の安定化制御を経由します。モーター PWM やサーボ出力を直接触りません。

---

## 1. 何がどこにあるか / Architecture

```
キーボード / ゲームパッド            js/gamepad/keyboard-provider.js
   押されているキーの集合                （通信手段を一切持たない）
        ↓ サンプル (axes[4])
正規化された操縦軸 -1..+1            js/pilot/pilot-axes.js
        ↓ forward / right / up / yaw
送信タイミングと停止条件              js/pilot/pilot-controller.js
        ↓ POST /api/drone/pilot/input   （15 Hz）
安全ゲートと単位変換                  backend/app/mavlink/pilot_service.py
        ↓ vx, vy, vz, yaw_rate [m/s, rad/s]
MAVLink 送信                          backend/app/mavlink/real_connection.py
        ↓ SET_POSITION_TARGET_LOCAL_NED
ArduPilot GUIDED（安定化制御）
```

ブラウザは MAVLink のメッセージ名も、フレームも、速度も知りません。
**-1〜+1 の4つの数値**を送るだけです。実際の速度を決めるのは全てバックエンド側で、
ブラウザを改造しても上限は上げられません。

**速度の設定は1か所だけです:** `backend/app/mavlink/pilot_limits.py`

## 2. キー割り当て / Key mapping

| キー | 動作 | 正規化軸 |
|---|---|---|
| ↑ | 前進 / forward | `forward` +1 |
| ↓ | 後退 / backward | `forward` −1 |
| ← | 左 / left | `right` −1 |
| → | 右 / right | `right` +1 |
| **W** | 上昇 / climb | `up` +1 |
| **S** | 下降 / descend | `up` −1 |
| **A** | 左ヨー / yaw left | `yaw` −1 |
| **D** | 右ヨー / yaw right | `yaw` +1 |
| **Space** | **移動中立 / neutral** | すべて 0 |

* 斜めは可能です（↑と→を同時に押すと前進しながら右へ）。
  **合計**の水平速度が上限を超えないよう、バックエンドが正規化します。
* 反対のキーを同時に押すと 0 になります（↑と↓ → 停止）。
* キーを離すとその軸は即座に 0 に戻ります。
* **Space は緊急モーター停止ではありません。** 速度ゼロを指令するだけです。
  ホバリング中の機体は「その場に留まる」という形でこれに従います。
  本当の緊急停止は送信機側の操作です。

キーが効かない状況（意図的な設計です）:

* 操縦を「有効化」していないとき
* テキスト入力・テキストエリア・セレクト・編集可能領域にフォーカスがあるとき

## 3. 速度上限 / Configured limits

| 項目 | 値 | 定数 |
|---|---|---|
| 水平（前後・左右の**合計**） | **0.30 m/s** | `PilotLimits.max_horizontal_speed` |
| 上昇 | **0.30 m/s** | `PilotLimits.max_climb_speed` |
| 下降 | **0.20 m/s** | `PilotLimits.max_descent_speed` |
| ヨー | **12 °/s** (= 0.2094 rad/s) | `PilotLimits.max_yaw_rate_deg` |
| 送信レート | 15 Hz | `SETPOINT_RATE_HZ` |
| 入力タイムアウト | 0.5 s | `PILOT_INPUT_TIMEOUT` |

下降を上昇より遅くしてあるのは、ボルテックスリングステート（自らの後流に
落ち込む状態）を避けるためと、地面に近づく方向の誤操作を穏やかにするためです。

変更する場合は `backend/app/mavlink/pilot_limits.py` の
`PilotLimits` の既定値だけを編集してください。他の場所に速度は書かれていません。

## 4. 座標系と符号 / Frame and sign conventions

送信するメッセージは `SET_POSITION_TARGET_LOCAL_NED`（ID 84）、
フレームは **`MAV_FRAME_BODY_NED` (8)**、type_mask は **1479**
（速度とヨーレートのみ有効、位置・加速度・ヨー角は無視）。

| 量 | 単位 | 正の向き |
|---|---|---|
| `vx` | m/s | **機首方向（前）** |
| `vy` | m/s | **右** |
| `vz` | m/s | **下**（NED なので、**上昇は負**） |
| `yaw_rate` | **rad/s** | **機首右回り** |

したがって:

* W（上昇） → `vz = −0.30`
* S（下降） → `vz = +0.20`
* D（右ヨー） → `yaw_rate = +0.2094`

ボディフレームなので、機首が向いている方向が常に「前」です。機体を 90° 回して
から↑を押すと、地面に対しては別の方向へ進みます。これは意図した挙動ですが、
**目視で機首方向を把握してから操作してください。**

## 5. 安全機構 / Safety mechanisms

ブラウザ側:

1. キーを離す → その軸は即 0
2. ウィンドウのフォーカス喪失（`blur`）→ 全キー解放 + **中立を即送信**
3. タブが非表示（`visibilitychange`）→ 同上
4. ページ離脱（`pagehide`）→ 同上
5. Space → 全キー解放 + 中立を即送信
6. Esc → 中立 + キーキャプチャ解除
7. キーは押下・解放を明示的に追跡します（ブラウザのキーリピートに依存しません）
8. 有効化するまでキーを一切奪いません。テキスト入力中も奪いません
9. 15 Hz で送信し続けます（押しっぱなしでも 200 ms ごとに必ず更新）

バックエンド側（すべて「通らなければ速度ゼロ」）:

10. `SUISUI_MAVLINK_ALLOW_PILOT_CONTROL=1` でなければ何も送りません
11. 操縦チャンネルが有効化されていなければ送りません
12. リンクが CONNECTED でなければ送りません（テレメトリ途絶も含む）
13. フライトモードが **GUIDED でなければ送りません**（モードを勝手に変えません）
14. アーム状態が**不明**なら送りません
15. DISARMED なら送りません
16. 直近の入力から **0.5 秒**を超えたら中立を送ります（`time.monotonic()` 基準）
17. リンクが切れたら保持していた指令を破棄します（再接続で復活しません）
18. 送信失敗は握り潰さず、状態に記録します

送らないもの: アーム、離陸、着陸、RTL、ミッション、モード変更、
`MAV_CMD_DO_SET_SERVO`、`RC_CHANNELS_OVERRIDE`、モーターテスト。
Pixhawk / ArduPilot 側のフェイルセーフは一切変更していません。

## 6. ArduPilot 側で確認すること / Before you fly

この機能は機体パラメータを変更しません。以下は**あなたが**確認する項目です。

| # | 項目 | 理由 |
|---|---|---|
| 1 | GUIDED モードが送信機のフライトモードスイッチに割り当ててある | GUIDED に入る・抜けるのは送信機で行います |
| 2 | `GUID_OPTIONS` が既定（0）である | 速度指令の解釈に影響します |
| 3 | GCS フェイルセーフ `FS_GCS_ENABLE` の設定を把握している | バックエンドは 1 Hz で GCS ハートビートを送ります。飛行中にバックエンドを止めるとフェイルセーフが作動します |
| 4 | `SYSID_MYGCS` がこのバックエンド（255）と一致、または GCS を限定していない | 一致しないと機体がコマンドを無視します |
| 5 | GPS 3D Fix と HDOP が良好（GUIDED は位置推定を必要とします） | 屋内では GUIDED に入れません |
| 6 | EKF が健全、コンパスキャリブレーション済み | ボディフレーム指令は機首方位に依存します |
| 7 | バッテリーフェイルセーフが設定済み | 変更していません。有効なままにしてください |
| 8 | 送信機の電波が届く範囲内である | 手動で取り返せることが前提です |

`GUID_TIMEOUT` 相当の挙動: ArduPilot は GUIDED で新しい目標が途絶えると
機体を停止させます。本バックエンドは中立を明示的に送るため、通常はその
タイムアウトを待つ前に止まります。

## 7. ベンチテスト手順（プロペラを外して）/ Bench test — PROPELLERS REMOVED

**この手順を飛ばさないでください。** 実際に機体が浮く前に、指令が期待どおり
出ているかを地上で確認します。

### 7.1 準備

1. **プロペラを4枚すべて外す。** 外したことを目視で確認する。
2. 機体を安定した台に置く。周囲に人がいないことを確認する。
3. QGroundControl を**完全に終了**する（COM ポートを共有できません）。
4. テレメトリ無線のアンテナが両方付いていることを確認する。
5. バッテリーを接続する。

### 7.2 起動

```powershell
.\scripts\dev.ps1 -Real -AllowSafeCommands -AllowPilotControl
```

`YES` と `PILOT` の2回の確認を求められます。

### 7.3 リンク確認（まだ動かしません）

6. ブラウザで `http://localhost:4173/#survey` を開く。
7. **ドローン / MAVLink** パネル: リンク状態「接続済み」、鮮度「正常」、
   アーム状態 **DISARMED** を確認。
8. **操縦（低速テスト）** パネルを開く。
   `MAVLink出力: 停止`、`ロック理由: 機体がDISARMED` と出ているはず。
   これが正常です。

### 7.4 入力の確認（DISARMED のまま）

9. 「操縦を有効化」を押す。`キーボード操縦: 有効` になる。
10. ↑ を押し続ける → `前後 / Fwd-Back` が `1.00` になることを確認。離すと `0.00`。
11. ↓ ← → W S A D を1つずつ試し、**期待した軸だけ**が動くことを確認する。
12. ↑ と ↓ を同時に押す → `0.00` になることを確認。
13. ↑ を押しながら Space → 全軸 0、緑の「movement neutralised」表示を確認。
14. ↑ を押したまま別のウィンドウをクリック（フォーカスを外す）→ 全軸 0 を確認。
15. `MAVLink出力` がこの間ずっと `停止` のままであることを確認する
    （DISARMED なので当然です。ここで `送信中` になったら**中止してください**）。

### 7.5 実際に指令が出ることの確認（プロペラは外したまま）

16. **プロペラが外れていることをもう一度確認する。**
17. 送信機で GUIDED を選ぶ。パネルの`フライトモード`が `GUIDED` になる。
18. 送信機で**アームする**（バックエンドはアームしません）。
19. `MAVLink出力` が `送信中` になり得ることを確認する。
    モーターがアイドル回転します。**プロペラが外れていることが前提です。**
20. ↑ を短く押す。QGroundControl は閉じているので、機体の傾き
    （前傾）を目視で確認する。プロペラがないので機体は動きません。
21. Space を押す。傾きが戻ることを確認する。
22. **送信機でディスアームする。**
23. パネルの「操縦を無効化」を押す。
24. バックエンドのターミナルで Ctrl+C。

ここまでで確認できたこと: キー割り当て、符号、中立動作、
GUIDED/アーム ゲート、送信経路。

## 8. 初回ホバーテスト手順 / First hover test

**7章のベンチテストを完了してから実施してください。**

### 8.1 場所と条件

* 屋外・**開けた場所**。半径 10 m 以上に人・建物・電線・車がない。
* 風 3 m/s 以下。降雨なし。
* GPS 3D Fix、衛星 12個以上、HDOP 良好。
* 補助者を1名（見張り役）。
* 送信機を持つ人（＝あなた）と、キーボードを操作する人を**分けてもよい**。
  分ける場合、キーボード側は「送信機側の指示があるまで触らない」。

### 8.2 手順

1. プロペラを取り付ける。増し締めを確認する。
2. バックエンドを 7.2 と同じコマンドで起動する。
3. リンク・GPS・バッテリーを確認する。**操縦パネルはまだ有効化しない。**
4. **送信機で通常どおり STABILIZE または ALT_HOLD で離陸する。**
   このアプリは離陸しません。
5. 高度 **2〜3 m** でホバリングさせ、安定を確認する。
6. 送信機で **GUIDED に切り替える**。機体がその場で保持することを確認する。
   （ここで異常があれば即座に STABILIZE に戻す。）
7. パネルの`フライトモード`が `GUIDED`、`アーム状態` が `ARMED` になっていることを確認。
8. 「操縦を有効化」を押す。
9. **最初のテスト: Space を押す。** 何も起きないことを確認する
   （すでに静止しているため）。停止指令が効くことを先に確かめます。
10. ↑ を **1秒だけ**押して離す。約 0.3 m 前進して止まることを確認する。
11. Space。
12. ↓ を1秒 → 後退して止まる。Space。
13. → を1秒 → 右へ。Space。← を1秒 → 左へ。Space。
14. D を1秒 → 機首が右に約 12° 回る。Space。A で戻す。Space。
15. W を1秒 → 約 0.3 m 上昇。Space。S を1秒 → 約 0.2 m 下降。Space。
16. **異常を感じたら、キーボードではなく送信機で STABILIZE に戻す。**
    これが常に最優先の対処です。
17. 「操縦を無効化」を押す。
18. **送信機で STABILIZE / ALT_HOLD に戻し、送信機で着陸させる。**
    このアプリは着陸しません。

### 8.3 中止条件（ひとつでも該当したら送信機で引き継ぐ）

* 意図しない方向へ動いた
* キーを離しても止まらない
* パネルの`MAVLink出力`が操作と食い違う
* テレメトリが途絶した
* バッテリー警告が出た
* 風が強くなった

## 9. トラブルシューティング

| パネルの表示 | 意味 | 対処 |
|---|---|---|
| `バックエンドで操縦が無効です` | `ALLOW_PILOT_CONTROL` が 0 | `-AllowPilotControl` を付けて起動し直す |
| `GUIDEDモードではありません` | 現在のモードが GUIDED でない | **送信機で** GUIDED に切り替える。アプリはモードを変えません |
| `機体がDISARMED` | 未アーム | ベンチテスト中はこれが正常。飛行時は送信機でアームする |
| `アーム状態不明` | HEARTBEAT がまだ届いていない | リンクの確立を待つ |
| `MAVLink未接続` / `テレメトリ途絶` | リンクが健全でない | 電波・アンテナ・距離を確認 |
| `入力タイムアウト → 中立` | 0.5 秒以上ブラウザから入力が届かなかった | ブラウザ/PC の負荷、Wi-Fi、タブの休止を確認 |
| `送信失敗` | シリアル送信に失敗 | ケーブル・ポートを確認。自動再接続を待つ |
| 軸は動くが `MAVLink出力: 停止` | 上のいずれかのゲートで止まっている | `ロック理由` を読む |

## 10. 残っているリスクと前提 / Remaining risks

* **SITL でも実機でも未検証です。** 実装・単体テスト・ブラウザテストは
  完了していますが、実際の ArduPilot に対して飛行させた記録はありません。
  7章のベンチテストが最初の実機確認になります。
* ボディフレーム指令は**コンパス方位に依存**します。方位がずれていると
  意図しない方向へ動きます。
* GUIDED は**位置推定に依存**します。GPS が劣化すると ArduPilot 側の
  挙動が変わります。屋内では使えません。
* ブラウザの `setInterval` は負荷やタブの状態で遅延します。0.5 秒の
  タイムアウトはこれを見越したものですが、極端に重い PC では
  「送信 → タイムアウト → 中立」を繰り返してカクつく可能性があります。
* ネットワークは 127.0.0.1 に限定されています。無線 LAN 越しの操縦は
  想定していません。
* 上限値は**保守的な初期値**であり、機体の実際の応答から決めたものでは
  ありません。ベンチと初回ホバーの結果を見てから調整してください。
* このアプリの停止手段（Space・フォーカス喪失・無効化）は**速度ゼロ指令**
  です。プロペラを止める手段ではありません。**モーターを止められるのは
  送信機だけです。**
